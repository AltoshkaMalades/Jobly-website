## 🚀 Запуск за 2 минуты

### Вариант 1: Автоматический интерактивный меню (РЕКОМЕНДУЕТСЯ)

```bash
cd classes-main

# Запустить главный демонстрационный скрипт
python demo_runner.py

# Выбрать:
# 1 - Только шаг 1 (5 минут)
# 2 - Только шаг 2 (5 минут)
# 3 - Только шаг 3 (5 минут, требует воркера)
# 4 - ВСЕ 3 (15 минут)
```

### Вариант 2: Запуск каждого отдельно

```bash
cd classes-main

# Демонстрация 1 (5 минут)
python demo_cicd_pipeline.py

# Демонстрация 2 (5 минут)
python demo_caching_performance.py

# Демонстрация 3 (5 минут, требует воркера в отдельном терминале)
# Терминал 1:
python manage.py celery -A core worker --loglevel=info

# Терминал 2:
python demo_async_tasks.py
```

### Вариант 3: Полная демонстрация с воркером (ЛУЧШЕ ВСЕГО)

```bash
# Открыть 3 терминала:

# Терминал 1: Celery воркер
cd classes-main
python manage.py celery -A core worker --loglevel=info

# Терминал 2: Главное меню
cd classes-main
python demo_runner.py
# Выбрать опцию 4 (все 3 демонстрации)

# Терминал 3: (опционально) Мониторинг Redis
redis-cli
> MONITOR
```

```
"Первое: Автоматизированный деплой (CI/CD).
Когда я делаю push на GitHub, всё происходит автоматически:
- Создается резервная копия БД (видите backup_*.sql файл)
- Применяются миграции
- Запускаются тесты
- Если все ОК → деплой на сервер
```

### Демонстрация 2 (3 минуты)
```
"Второе: Кэширование и производительность.
Один и тот же запрос к БД:
- БЕЗ кэша: 250 миллисекунд (каждый раз в БД)
- С кэшем: 5 миллисекунд (из Redis памяти)

Это ускорение в 50 раз! Представьте 1000 пользователей
- Без кэша: затоп в БД
```

```
Решение: Асинхронность с Celery
- Задача отправляется в очередь (за <100ms)
- Сайт сразу отвечает
- Celery воркер (видите второе окно) выполняет в фоне
- Пользователь счастлив!"
```

## 🐛 Если что-то не работает

### Redis не запущен
```bash
# Запустить Redis
redis-server

# Или в Docker
docker run -d -p 6379:6379 redis:alpine
```

### Celery воркер не подхватывает задачи
```bash
# Переустартить с дебагом
python manage.py celery -A core worker --loglevel=debug

# Проверить очередь
redis-cli LLEN celery
```

### Ошибка импорта Django
```bash
# Убедитесь что находитесь в классе
cd classes-main

# Активируйте виртуальное окружение (если используется)
source .venv/bin/activate  # Linux/Mac
.venv\Scripts\activate      # Windows
```
